****# Reader

## Project

A local read-aloud app for one user. Paste Markdown, press a button, hear it read with the sentence and the spoken word highlighted. It replaces Edge's Read Aloud, which keeps failing. A Node server and a React page on localhost, with speech from HeadTTS (the Kokoro model, on CPU). `pnpm start` builds the page and serves it at `http://localhost:4400`, which Windows opens too. `pnpm dev` runs the server with Vite's live-reload page on port 5173. It never runs beside the service or `pnpm start` (same ports, same `data/`) and refuses to start then: `pnpm service stop` first, `pnpm service start` when done. `pnpm service on|off|start|stop|restart|status` (`scripts/service.ts`) keeps `pnpm start` running as a systemd user service; while it is on, code changes take effect only after `pnpm service restart`. Ticket `rd-1` holds the design decisions.

- `server/main.ts`: HTTP routes and the built page. `server/store.ts`: documents in `data/docs/`, settings in `data/settings.json`, and the archived groups in `data/groups.json`. Each window's tabs, their order and the current tab are a workspace in `data/workspaces/<name>.json`, named by `?w=<name>` in the page's address. A bare address claims the workspace used most recently that no window has open (windows ping every 20 s and release on close), else a new one, and the page writes the name into its address. A workspace idle for 7 days with no window open is deleted with its documents. A test server runs with `READER_DATA=tmp/e2e/data`, since the user's service on port 4400 reads and writes `data/` live. `server/speech.ts`: the sentence cache in `data/cache/`, keyed by the prepared HeadTTS input; a cache read refreshes a file's time, and files unused for 2 days are deleted at start and daily. `server/pronunciation.ts`: picks the sounds of every word before HeadTTS (fixes in `pronunciation/fixes.tsv`, units read after a number in `pronunciation/units.tsv`, misaki's dictionaries in `pronunciation/misaki/`; every file explained in `pronunciation/README.md`), and logs words nothing knows to `data/pronunciation/unknown.jsonl` (that folder, with the flags and `reviewed.txt`, is tracked in git so it syncs through the private repo; the rest of `data/` is ignored); `pnpm test` checks it, and every line of `pronunciation/checks.jsonl`. The TSV files keep a header row and the same field count on every row, so CSVLint passes. `server/feedback.ts`: the reader's right-click "Flag…" saves a flag to `data/pronunciation/flags.jsonl` with the exact HeadTTS input and the Markdown of the sentence's block (`Sentence.source` in `web/src/reading/segment.ts`). Fixes come only from investigating flags, and each confirmed fix adds a test line to `checks.jsonl`. The user runs `/investigate-flags`, which follows `pronunciation/investigate.md` through `pnpm flags` (`scripts/flags.ts`); `pnpm flags bundle` makes the same instructions plus the data for a model with no tools. The compromise library tags each word noun, verb or adjective, which picks among misaki's sounds for words like "use". `server/guesser.ts`: misaki's AI model in `pronunciation/misaki/guesser/`, which guesses the sounds of a word no list knows. `server/spoken.ts`: finds paths in the page's labelled pieces (plain text, inline code, links) and says them innermost first, or left to right with "slash" when `pathStyle` in `data/settings.json` is `slashes`. It says a bare link as its site plus the words in its address; site exceptions (spoken name, search parameter, parts to drop) are data in `pronunciation/sites.json`, never code. `server/providers/headtts.ts`: starts and calls HeadTTS. A new speech engine is a new provider of the shape in `server/providers/types.ts`. Node 24 runs the `.ts` files directly; the root `tsconfig.json` only type-checks them, and `pnpm typecheck` checks the server and the page.
- `web/`: the page, React with TypeScript, Vite, Tailwind and shadcn components (`web/src/components/ui/`, added with `pnpm dlx shadcn@latest add`). `web/src/reading/`: Markdown rendering and sentence splitting (`render.ts`, `segment.ts`), code blocks drawn like GitHub's, with Shiki colours, wrapped lines and a copy icon on hover (`code-block.tsx`), playback and word timing (`player.ts`), the highlight boxes (`highlighter.ts`). `web/src/components/`: tab bar, reader view, player bar, the right-click "Flag…" menu and its box (`flag-menu.tsx`). `web/src/archive/`: the grouped sidebar and the Library sidebar, both replaced by tabs and kept whole so they can return.
- `docs/context/requirements.md`: what version 1 must do.
- `docs/context/headtts-setup.md`: how HeadTTS runs and is called.
- `docs/context/headtts-findings.md`: the prototype's test results.
- `docs/context/vision.md`: background only.
- `tts/`: the HeadTTS config, the 28 English voice files, and a client from the prototype.

## Rules

- **`prototype-mode`** Build fast and improve by use: the user needs it working within hours. Make the technical calls yourself and name each in one line. Add what makes the app usable past `requirements.md`. Ask the user only about requirements, layout and features.
- **`pnpm-only`** Install and run with pnpm, never npm. A dependency with a build script needs `pnpm approve-builds`.
- **`user-commits`** The user commits. Never commit, and never suggest a commit or end a reply with one.
- **`no-notes`** Never run `flow note`. File deferred work and ideas as a ticket, or a line in a ticket's `## Tasks`.
- **`one-sentence-per-synthesis-call`** Send HeadTTS one sentence per request. A longer input changes the prosody, so cached audio and word timings stop matching.
- **`explain-speech-from-zero`** The user knows none of the speech tools (HeadTTS, Kokoro, misaki, sound spellings) or how Reader's steps connect. A tool gets one line on its job here before its name appears.
  - **`picture-on-new-parts`** A reply that introduces a new part, or answers a request for the full picture or how parts fit, shows a diagram built on the 5 steps in `.flow/tickets/7/speech-pipeline.md` with the part in place, and each step's real input and output from a run. Other replies get no diagram.
- **`strip-punctuation-before-matching`** Strip punctuation from HeadTTS `words` and from page words before comparing them.
